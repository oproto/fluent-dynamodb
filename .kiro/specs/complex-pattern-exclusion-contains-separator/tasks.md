# Implementation Plan

## Overview

Fix the tautological `Contains("<separator>")` exclusion guard generated by `PatternOverlapAnalyzer.CreateExclusionPattern()` when a Complex pattern like `"CAP#*#*"` overlaps with a simpler `"CAP#*"` StartsWith pattern. The fix introduces positional `IndexOf` checks, semantic subsumption detection, and non-discriminating clause omission.

  - [x] 3.1 Add OffsetIndex property to ExclusionPattern model
    - File: `Oproto.FluentDynamoDb.SourceGenerator/Models/ExclusionPattern.cs`
    - Add `public int OffsetIndex { get; set; }` property
    - When `OffsetIndex > 0`, the code generator emits `IndexOf(LiteralText, OffsetIndex) >= 0` instead of `Contains(LiteralText)`
    - Default value of 0 means existing behavior is unchanged (backward compatible)
    - _Bug_Condition: isBugCondition(input) where internal segment length <= separator length AND prefix contains the segment_
    - _Expected_Behavior: exclusion.OffsetIndex == prefixSegment.Length for bare-separator cases_
    - _Preservation: All existing ExclusionPattern usages continue to work with OffsetIndex defaulting to 0_

  - [x] 3.2 Fix CreateExclusionPattern() to detect bare-separator segments
    - File: `Oproto.FluentDynamoDb.SourceGenerator/Analysis/PatternOverlapAnalyzer.cs`
    - After extracting internal segments from Complex pattern split on `'*'`, check whether the last segment is a bare separator
    - A segment is "bare" when: `prefixSegment.Contains(lastSegment)` AND `lastSegment.Length <= separatorLength`
    - When bare-separator detected: set `OffsetIndex = prefixSegment.Length` on the returned ExclusionPattern
    - When multiple internal segments exist and last is bare, try earlier segments; if ALL are bare, use positional approach with first bare separator
    - Strategy remains `Contains` but OffsetIndex signals the generator to use `IndexOf` instead
    - _Bug_Condition: isBugCondition(input) where segments from Split('*') produce bare separator as last internal segment_
    - _Expected_Behavior: CreateExclusionPattern returns ExclusionPattern with OffsetIndex = prefix.Length for bare-separator cases_
    - _Preservation: Patterns with meaningful internal segments (e.g., "#LINE#", "#ROLE#") continue to return OffsetIndex = 0_
    - _Requirements: 2.1, 2.2, 2.3_

  - [x] 3.3 Fix IsTautologicalExclusion() for semantic subsumption detection
    - File: `Oproto.FluentDynamoDb.SourceGenerator/Analysis/PatternOverlapAnalyzer.cs`
    - Expand the existing identity check to also detect semantic subsumption
    - If exclusion strategy is `Contains` and positive strategy is `StartsWith`: check if the positive literal contains the exclusion literal → tautological
    - If exclusion strategy is `Contains` and positive strategy is `Complex`: extract prefix from Complex pattern and check same containment → tautological
    - This serves as a safety net: even if `CreateExclusionPattern()` somehow produces a bare-separator without OffsetIndex, this catches it
    - _Bug_Condition: IsTautologicalExclusion returns false for Contains("#") vs StartsWith("CAP#") — fails to detect subsumption_
    - _Expected_Behavior: IsTautologicalExclusion returns true when exclusion literal is inherently contained in positive prefix_
    - _Preservation: Identity-based tautology detection (same Strategy AND same LiteralText) continues unchanged_
    - _Requirements: 2.4_

  - [x] 3.4 Fix GenerateComplexPatternCheck() to omit non-discriminating Contains
    - File: `Oproto.FluentDynamoDb.SourceGenerator/Generators/MapperGenerator.cs`
    - In the conditions-building loop for Complex patterns, skip any internal segment whose literal text is already contained within the first segment (prefix)
    - For `"CAP#*#*"`: skip `Contains("#")`, produce just `StartsWith("CAP#")`
    - For `"CAP#*#*#LINE#*"`: skip `"#"` but keep `Contains("#LINE#")`
    - For `"INVOICE#*#LINE#*"`: keep `Contains("#LINE#")` unchanged (segment is meaningful)
    - _Bug_Condition: GenerateComplexPatternCheck produces StartsWith("CAP#") && Contains("#") where Contains adds zero filtering power_
    - _Expected_Behavior: Non-discriminating Contains clauses omitted from positive Complex pattern checks_
    - _Preservation: Meaningful Contains clauses (e.g., Contains("#LINE#")) preserved unchanged_
    - _Requirements: 2.5_

  - [x] 3.5 Fix exclusion generation in MapperGenerator to handle OffsetIndex
    - File: `Oproto.FluentDynamoDb.SourceGenerator/Generators/MapperGenerator.cs`
    - In `GenerateDiscriminatorCheckWithExclusions()` (exclusion emission loop), for `DiscriminatorStrategy.Contains` case:
    - Check if `exclusion.OffsetIndex > 0`
    - If yes, emit: `if (discriminatorValue.S.IndexOf("<literal>", <offset>) >= 0) return false;`
    - If no (OffsetIndex == 0), emit existing: `if (discriminatorValue.S.Contains("<literal>")) return false;`
    - _Bug_Condition: Exclusion with bare separator emits Contains("#") which is always true after StartsWith("CAP#")_
    - _Expected_Behavior: Exclusion with OffsetIndex > 0 emits IndexOf("#", 4) >= 0 which correctly discriminates_
    - _Preservation: Exclusions with OffsetIndex == 0 continue to emit Contains() as before_

- The fix is separator-agnostic: it works for any separator character (#, _, :, etc.)
- The OffsetIndex approach is backward-compatible: existing exclusions default to 0 and continue using Contains()
- Integration tests require compiling test entities through the source generator pipeline
